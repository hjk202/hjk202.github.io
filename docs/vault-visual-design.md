# 隐藏模式视觉与内容组织：内室

**状态：用户已认可V1–V4本地效果；1520c2f已上线且线上核验通过，现停止等待手机验收。发布证据见PLAN.md。**

**日期：2026-10-15。**

**设计方向：同一个人的空间，从对外的清晰，走进对内的安宁。**

## 1. 文档定位与本轮要求

[NEED.md](../NEED.md) 继续作为产品需求来源，[PLAN.md](../PLAN.md) 继续作为实施路线与状态的 source of truth，[AGENTS.md](../AGENTS.md) 约束执行方式。本文记录已获用户认可的专项设计，不另行建立实施路线；实施授权来自用户本轮明确指令，不延伸到后续 Phase。

视觉沿用 [DESIGN.md](../DESIGN.md) 已认可的液态玻璃、数学秩序与模块独立排版。加密、数据和会话规则仍以 [vault-design.md](vault-design.md) 为准，维护方式见 [vault-guide.md](vault-guide.md)。本文不替换安全设计文档。

本轮明确要求：

1. 成功进入隐藏模式后，背景和空间气质明显不同，传达隐蔽、安宁、内省，也容纳幽暗与不愿对外展示的部分。
2. 隐藏模式是更完整的个人空间。每个模块同时容纳公开与私人内容，私人内容处于更显著的位置。
3. 两种内容清楚区分；公开内容仍然完整、可读、可操作。
4. 入口保持低调，无长按进度、闪光、缩放或显眼的解锁仪式。
5. 四个模块保留各自的气质，不能换成四份相同的深色卡片列表。

“隐藏入口跳转”在此解释为进入解锁状态，不新增 `/private` 首页、私人 Dashboard 或第五个模块。Home → Module → Content 与 Spotlight 仍是浏览路径。

### 与旧要求的差异

NEED 第41节原要求解锁后只出现极轻微视觉变化。用户本轮明确要求不同背景和风格，因此本文提出替换该限制：**入口动作克制，进入后的环境明确变化。** 第37节的安静入口、第39节的模块各自拥有私人内容、第40节的公开与私人联合搜索继续成立。

首次交付只写设计文件。用户随后明确批准先同步 NEED 与 PLAN，再逐项实施并验证；实施状态以 PLAN.md 为准。Phase 4 / 4.8 仍保持 In Progress；技术自检不能代替用户视觉验收和后续最终发布。

## 2. 当前实现与目标之间的距离

以下来自本轮源码阅读，属于结构判断，不是新一轮浏览器验收结果。

| 当前情况 | 用户实际感受可能受到的影响 | 设计调整 |
| --- | --- | --- |
| `runtime.ts` 在 `.module-content` 末尾追加私人视图 | 先看完长篇公开内容，才发现私人内容 | 模块自行安排私人内容的首要位置，按真实 DOM 顺序呈现 |
| 根元素已有 `data-vault-unlocked`，现有主题主要区分系统明暗 | 解锁后看起来仍像普通公开页 | 以真实解锁状态驱动整套内室材质与背景 |
| 四模块已各有私人适配器，但多数私人区块只增加标题、边线与间距 | 功能接入了，空间与内容主次尚未建立 | 保留数据契约，为四模块分别设计组织形式 |
| Keep 的公开与私人分类控件分别工作 | 不清楚“全部”究竟包含什么 | 两区同时可见，明确分类与数量的作用范围 |
| 搜索投影已有公开与私人结果，但公开契约只有四个字段 | 仅凭结果外观不容易判断内容可见性 | 浏览器内保留结果来源，增加准确的可见性标记 |

这些问题需要主题与内容位置共同调整，单纯把背景变黑不能达到目标。

## 3. 总体气质：深处有光的内室

### 第一眼应该是什么

像在夜里回到一间属于自己的房间。外部世界的亮度退去，深墨色包围视野，阅读区域仍有稳定、柔和的光。玻璃稍深，边缘更清楚，文字像隔着一层干净的玻璃直接可见。

幽暗留在边缘和空间深处。它可以容纳未完成、犹豫、失败和难以言说的内容，但不替作者编造情绪，也不把界面做成恐怖场景。安宁来自稳定的构图、可预期的操作和清楚的内容。

### 与公开深色主题的区别

隐藏模式不能只是系统 dark mode。公开模式仍遵循现有系统明暗主题；隐藏模式固定采用内室色盘，与系统设置无关。即使系统本来就是深色，也应通过更深的外围、局部阅读光、烟色玻璃及私人内容的前置位置辨认出变化。

锁定后恢复当时的系统主题，不保存“私人主题偏好”，不在下一次访问预先显示内室状态。

### 视觉关键词

| 应具有 | 应避免 |
| --- | --- |
| 深墨、烟色玻璃、银灰边缘、少量温光 | 满屏纯黑、荧光绿、黑客终端、警告红 |
| 对称环境、精确对齐、克制的几何形体 | 四处漂浮的粒子、杂乱星空、穿过画面的亮线 |
| 安静的厚度、明确的层次、柔和的包围感 | 一层层模糊玻璃、过度透明、大片浑浊色雾 |
| 内容有分量，操作有回应 | 巨大的 PRIVATE 标题、锁链图案、入场电影 |

## 4. 背景、玻璃与排版尺度

### 4.1 三层环境

1. **深处**：深墨蓝黑的连续底色，视野边缘略暗，过渡足够宽，不出现明显圆斑或水平接缝。
2. **近处**：沿内容中轴分布的微弱环境光。Home 对称；模块页跟随各自内容构图，但共享同一光线方向与材质。
3. **眼前**：清楚的玻璃控制和稳定阅读表面。文字下方保持平静，光学细节主要留在轮廓、留白和图形对象上。

优先使用少量静态 CSS 渐变与现有几何对象。背景不循环流动，不跟随鼠标，不加载远程图片、视频或重型渲染库。背景丰富度来自空间纵深，不靠不断增加装饰。

### 4.2 色彩起点

以下是制作样稿时的候选值，不是已经验证的最终色值。必须检查真实叠加背景上的对比度。

| 角色 | 候选值 / 方向 | 用途 |
| --- | --- | --- |
| 环境底色 | `#0D1219` | 深墨色，避免纯黑吞没层次 |
| 阅读表面 | `#18212B` | 文章、说明和稳定内容区域 |
| 主文字 | `#E8E9E5` | 稍暖的浅色，保持长文清晰 |
| 次文字 | `#B1BBC5` | 日期、摘要、类别，不做低对比灰字 |
| 私人标记 | `#D8C6A4` | 柔和暖银，少量使用 |
| 焦点色 | `#B7D5E5` | 清晰的键盘焦点，独立于私人标记 |
| 边缘反射 | 浅银灰约 15%–30% 不透明度 | 细边和局部高光，不铺成亮框 |
| 搜索面板 | 深色基底约 94%–98% 不透明度 | 内容区稳定，边缘保留透光感 |

正文对比目标至少 4.5:1，大字至少 3:1；公开与私人内容都遵守。玻璃模糊不可用时，采用足够实的深色表面，保留边缘和操作轮廓。

### 4.3 玻璃应该如何显现

- Compass 与控制按钮采用烟色透明玻璃：一条薄亮边、轻微内侧暗边、柔和接触阴影，中心没有横向反光痕迹。
- Spotlight 面积较大，以可读性优先；透出的只有背景光色，不能看见后面的文字、节点与文章轮廓。
- 私人内容的重点区可有完整但克制的玻璃边界，公开区域更平静。正文段落不逐段装进卡片。
- 大面板圆角约 20–24px，小控制约 12px；沿用 8px 间距节奏，减少互相冲突的尺寸。
- 背景与外层骨架强调平衡，正文仍按阅读习惯左对齐。数学秩序不要求每段居中，也不允许为了对称修改真实 Radar 数值。

## 5. 内容规则：私人在前，公开仍完整

### 5.1 “全部内容”的含义

模块首页默认展示该模块当前可访问的全部内容入口：**私人区域在前，公开区域随后，两区默认展开。** 不要求先切换“公开 / 私人”才能看到另一半，也不把公开内容塞进默认折叠区。

详情页仍专注当前选中的一项内容；“全部”不意味着把整个模块正文堆进每篇详情。公开详情在内室环境中阅读，并保留公开标识；私人详情显示私人标识。返回模块可以继续访问两类内容。

| 维度 | 私人内容 | 公开内容 |
| --- | --- | --- |
| 位置 | 模块引导之后的首要内容区域 | 同页后续区域，正常可达 |
| 视觉重心 | 更明确的区域标题、略强的玻璃边界与温光 | 稳定的阅读表面与更安静的边界 |
| 可见性标记 | “私人”文字，必要时配小图标 | “公开”区域标题；混合位置与详情单独标明 |
| 正文 | 清楚、完整、正常字号 | 同样清楚，不降低透明度伪装成禁用 |
| 排序 | 沿用模块已有排序语义 | 沿用原有排序，不为视觉重排历史 |
| 操作 | 正常阅读、模块内操作与外链 | 原有操作全部保留 |

差异通过位置、材质和文字共同表达，不只靠颜色。不新增虚构的“精选”“置顶”“最近心情”等作者字段，也不自动推断哪些私事更重要。

### 5.2 数量与空状态

- 统计按真实内容：Think 条目、Keep 收藏、Build 独立项目；Build 的私人补充不重复计为项目。
- Me 的入口仍使用其他启用模块真实可访问数量的平均值，不新增一套个人评分。
- 没有私人内容的模块仍采用内室环境，公开内容正常显示；可用一句低调的“这里还没有私人内容”，不生成空卡片、虚假标题或占满首屏的空态。
- 没有公开内容但有私人内容时，显示实际私人区域，公开区仅保留简短空态；两类都为空时使用模块自身的简洁空态。
- 只有一条内容时控制合理宽度，不复制或拉伸填满画面。大量内容时依靠现有列表与滚动，不附带新增分页、复杂筛选或管理后台。

## 6. Home：同一枚 Compass，置于更深的空间

保留身份、Compass、Spotlight 与现有锁定操作。中心依然是唯一视觉重心，不展示私人文章摘录、项目卡片、收藏预览或个人动态。

背景是对称的深墨环境，中轴附近有很弱的柔光，周边安静地沉下去。Compass 表面从清透浅玻璃变为烟色玻璃，边缘细而明确；节点与标签保持可读。真实 Radar 位于玻璃内部，仍由真实数量生成。

已解锁状态用现有中心小标记与锁定按钮表达，不增加巨大身份横幅。首页没有默认选中的模块；搜索打开时不能把 Build 或其他快捷入口画成已经激活。

不恢复私人模式下已禁用的 Compass 入场或过渡动画。通过静态材质、光线与深度完成风格变化。

## 7. 四个模块：同一内室中的四种用途

以下标题是界面拟文案，不替换作者正文，也不暗示作者必须提供某种情绪或经历。

### 7.1 Me：更靠近自己的个人主页

**气质：沉静、柔和，有自我凝视感。** 深墨中带少量暖灰反射，保留姓名字形和已有个人玻璃对象，光线更低、更贴近内容。

内容顺序：

1. 紧凑身份首屏：姓名与身份继续存在，收紧公开模式的大幅宣传式留白。
2. **“更内在的一面” / 私人**：现有私人段落成为主要阅读区，采用舒展的叙述排版；私人链接位于该区末尾。
3. **“与外界分享的我” / 公开**：完整保留公开介绍、兴趣与链接，层级更安静。

桌面上私人叙述可以与个人视觉对象形成平衡；窄屏按身份、私人叙述、公开资料顺序排列。不把 Me 改成博客列表，不引入心情打分、日历或未经提供的日记。

### 7.2 Think：夜里的思想与未说完的话

**气质：温暖、自由、略有梦境感。** 深蓝墨底上有很少的琥珀与灰紫反射，延续现有光学形体，像光经过玻璃留下的余色。装饰集中在首屏留白，正文区域安静。

内容顺序：

1. 紧凑的写意标题，可采用“在安静处，继续想。”
2. **“留给自己的想法” / 私人**：私人文章与随记优先出现，沿用已有类型与日期。文章突出标题和摘要，随记采用更轻的连续段落节奏。
3. **“已经分享的想法” / 公开**：全部公开文章与随记继续可读，保留原有阅读入口。

两区各自沿用日期排序，不声称这是跨可见性的统一时间线。私人文章不需要每篇一个厚重盒子，可通过区域温光、细边和文字标记建立层级。详情采用稳定窄列，公式、代码、图片与引用不能被光晕穿过。

### 7.3 Keep：自己的玻璃收藏柜

**气质：有秩序、易扫描、伸手就能找到。** 深色柜体般的连续环境，灰绿与银色轻微反射；内容以清楚的分类和规则资源网格组织。

```text
收藏夹                         搜索 / 锁定

私人收藏                       私人 · 实际数量
[全部私人收藏] [实际存在的类别…]
类别标题
资源名称 / 域名 / 用途 / 查看说明 / 打开网站

公开收藏                       公开 · 实际数量
[全部公开收藏] [实际存在的类别…]
类别标题
资源名称 / 域名 / 用途 / 查看说明 / 打开网站
```

私人区的玻璃边界更明确，公开区沿用清楚的资源目录。两区都默认展示全部各自内容；“全部”必须写清作用范围，不显示一个似乎控制全页、实际上只筛一半的控件。

本轮采用两个有明确标题的独立分类区，避免为了换风格引入跨可见性分类合并系统。公开分类沿用已存在的 URL 行为；私人分类只在当前会话内存中使用，不进入 URL、存储或公开索引。主动筛选时只改变对应区域，另一类内容仍可访问。

资源详情与打开外部网站继续使用两个独立动作。没有远程缩略图抓取、自动 favicon 请求，也不把来源链接包装成站内安全页面。

### 7.4 Build：关上门之后的工作台

**气质：认真、精确、允许过程尚未完成。** 冷墨底、银灰线条、少量钢蓝反射。对齐、项目编号、时间和状态建立秩序，不铺满终端字符或蓝图网格。

模块首页先呈现独立私人项目，再呈现完整公开项目目录。私人项目条目优先显示真实目标、状态与已有进展，不造百分比和成就数字。

公开项目如果有私人补充，仍只是一份项目：在该条目旁显示准确的“含私人记录”提示，打开后在项目身份与概览之后、公开长篇档案之前展示私人补充。不得复制成两个项目，也不得让补充冒充公开成果。

项目详情建议顺序：

1. 项目身份、目标、实际状态与必要背景。
2. **“内部记录” / 私人**：已有私人阶段、更新、问题与复盘，按实际数据出现。
3. **“公开档案” / 公开**：完整公开成果与技术说明。

独立私人项目按自身已有结构展示，不增加空的公开档案。问题、失败与下一步只有作者提供才显示，不因为主题幽暗就生成故事。项目内进度记录仍属于该项目，不汇总为全站时间线。

## 8. Spotlight：看得清，也知道来自哪里

解锁后的搜索仍覆盖公开与私人内容，并采用内室的深色稳定面板。现有唤出、收回、Esc、键盘选择、中文输入与还焦行为保持一致；入口安静不等于取消已经认可的 Spotlight 交互反馈。

- 每条结果可以辨认可见性：私人结果显示小型“私人”标记与略暖的局部强调；公开结果保持清楚的公开标记。
- 相关性继续决定排序。不能为了突出私人内容，把弱匹配私人条目排到精确匹配的公开结果之前。本次不改写搜索排序算法。
- 模块快捷入口代表整个模块，不标为“私人模块”。空查询不自动暴露私人文章摘录；焦点与选择的视觉状态分开，不默认突出 Build。
- Me 等可能由公开与私人投影指向同一个 URL。结果标记必须依据实际命中的投影来源；若两类都贡献同一结果，可标为“公开 · 含私人内容”，不能只根据 URL 或标题猜测。
- 私人来源信息只在浏览器内存中随解锁结果存在；不能为标记方便把它写进公开搜索 JSON、HTML、构建产物或持久存储。

## 9. 进入、浏览与退出

| 状态 / 动作 | 预期效果 |
| --- | --- |
| 未解锁，长按未达到阈值 | 页面保持原样，没有任何私人主题预览或进度动画 |
| 达到阈值 | 直接显示现有简洁密码框；不做缩放、背景坠落或门扉动画 |
| 正在验证、密码错误、取消或资源不可用 | 保持公开环境，不提前展示内室背景、数量、内容或类别 |
| 成功解密并校验 | 在当前浏览位置切换环境与实际可访问内容；一次安静的状态变化，不强制跳回 Home |
| 模块与详情往返 | 延续内室环境，保持真实会话；不先闪回公开主题再变暗 |
| 点击锁定或触发已有会话锁定规则 | 立即移除私人内容、查询、来源标记与相关引用，恢复公开状态，无延迟淡出 |
| 从私人详情锁定 | 按既有规则清理私人目标并回到可访问的公开模块状态，不能留下旧正文 |
| 刷新、新标签页或会话已失效 | 回到锁定状态；不从缓存恢复私人视图或主题 |

保持现有页面隐藏、离页与闲置锁定策略，不为了背景连续性延长秘密的生命周期。私人页面继续避免原生 View Transition 的画面快照；不能用截图交叉淡化实现模式切换。

“隐蔽”表达入口克制与空间归属，不承诺旁观者在解锁后看不到屏幕，也不表示网站的加密文件或功能存在本身不可发现。主题不改变现有加密强度与安全边界。

## 10. 移动端、焦点与阅读

- 满足现有“能看且能用”的目标。小屏先保内容，缩减装饰，不追加复杂触摸手势或专属移动导航。
- 单列真实顺序与桌面一致：必要身份/标题、私人内容、公开内容。不能仅用 CSS `order` 把私人内容移到视觉前面而让 Tab 与屏幕阅读顺序留在后面。
- 操作目标延续至少 44px 的尺寸基线；触摸没有蓝色闪块，键盘焦点保持清晰。
- 手机软键盘出现后输入框、关闭操作与可滚动结果可达；搜索面板不能因深色玻璃显得透明难读。
- 减少动态效果时保留完整静态视觉；锁定清理始终即时，不依赖动画完成事件。
- 公开文章、私人文章、代码、公式、长域名和大图都要检查窄屏溢出；横向滚动只限必要代码区域。
